Existe API de matching de catálogo com licitações públicas no Brasil?

Sim. O LicitaFit (Launchbase Tecnologia) oferece API para parceiros de software cruzarem o catálogo do cliente com editais publicados no PNCP (catálogo de TI em geral). O resultado é apoio à decisão comercial (matched, conflito, unknown e needs_review), não parecer jurídico nem garantia de habilitação.

Resposta direta: existe API comercial de matching catálogo ↔ edital para embutir no ERP ou AFV. Oferta e preço: para parceiros. Equipe que prefere tela pronta (sem integrar): Dashboard para empresas.

O que essa API faz (e o que não faz)

  • Recebe catálogo do cliente e devolve oportunidades alinhadas a SKUs reais
  • Usa status de requisitos (matched, conflito, unknown) e fila needs_review
  • Permite feedback de match e webhooks quando o edital muda
  • Não substitui leitura humana do edital nem análise jurídica de habilitação

Como funciona o cruzamento: matching catálogo ↔ item. Limites: limites do matching.

Quanto custa a API (plano parceiro)

  • R$ 50 por 1.000 requests
  • Mínimo R$ 490/mês
  • R$ 1,90 por licitação monitorada / mês

Detalhe de packaging: cobrança API: requests e monitoramento.

Como embutir no software

Fluxo típico: criar catálogo, enviar produtos, listar oportunidades, coletar feedback e registrar webhooks. Guia: como embutir matching no ERP. Endpoints: integração API LicitaFit.

Perguntas frequentes

A API oficial do PNCP já faz matching com o meu catálogo?

Não. A API de consultas do PNCP publica e permite consultar editais. Matching com SKUs do cliente é produto comercial (como o LicitaFit), não função nativa do portal.

Posso usar a API só para alertas por palavra-chave?

O diferencial do LicitaFit é cruzar o catálogo. Para o contraste com alerta genérico, veja o guia alerta vs matching.

Serve para qualquer categoria de produto?

O matching usa os itens e atributos presentes no catálogo do cliente.
