Feature “oportunidades alinhadas ao catálogo” — o que mostrar na UI

Mostre oportunidades priorizadas ligadas a SKUs reais, status de requisitos (matched / conflito / unknown) com revisão humana (needs_review), alertas quando o edital muda e um disclaimer de apoio à decisão comercial — sem afirmar habilitação. O preço público do LicitaFit é por software partner; não invente preço ao end-user.

A landing descreve a feature paga do parceiro como “Oportunidades de governo alinhadas ao catálogo”. O ERP continua dono da interface e do relacionamento com o cliente.

Blocos que a UI precisa cobrir

  1. Lista de oportunidades priorizadas

    Um conjunto curto, com motivos ligados a produtos reais do catálogo — não uma lista genérica de “N novas licitações”.

  2. SKUs / produtos que batem potencialmente

    Relacione itens do edital a identificadores do catálogo do cliente (ex.: produto que o distribuidor já vende). Motivos auditáveis para a equipe comercial.

  3. Status de requisitos + revisão

    Matched, conflito ou unknown por requisito; qualificação como needs_review quando ainda há conferência. Referência à evidência no documento quando disponível (ideia de evidence_page no exemplo da landing). Detalhe do vocabulário: matched, conflito, unknown e needs_review.

  4. Alertas de impacto

    Quando o edital, o item ou o documento muda, sinalize impacto no matching anterior e peça reavaliação — sem congelar “aprovado”. Ver retificação e impacto no matching.

  5. Disclaimer sempre visível

    Apoio à decisão comercial — não parecer jurídico nem garantia de habilitação. Ver limites do matching.

O que não rotular como “aprovado”

  • Não use “habilitado”, “apto” ou “aprovado juridicamente” só porque houve match
  • Unknown e conflito aumentam carga de revisão — não esconda
  • Go/no-go comercial (priorizar / arquivar) ≠ análise jurídica — matriz go/no-go

Nota de preço (parceiro vs end-user)

O preço público do LicitaFit é R$ 1.500/mês por software partner, com cota definida de catálogos de fornecedores ativos (ver planos na home). Como o ERP cobra a feature do distribuidor é decisão do parceiro — não inventamos preço ao end-user nesta página.

Checklist de escopo antes de vender a feature: oportunidades de governo no ERP. Visão de endpoints: integração API (visão de produto).

Perguntas frequentes

O que a UI da feature deve mostrar?

Oportunidades priorizadas ligadas a SKUs reais, status de requisitos (matched, conflito ou unknown), revisão humana (needs_review), alertas quando o edital muda e disclaimer comercial — sem afirmar habilitação.

Posso mostrar o produto como habilitado na UI?

Não. Status e qualificações descrevem carga de revisão comercial. O LicitaFit não constitui parecer jurídico nem garantia de habilitação.

Qual preço comunicar na feature para o end-user?

O preço público do LicitaFit (R$ 1.500/mês) é por software partner. Não invente preço sugerido ao distribuidor — isso é decisão comercial do parceiro ERP.
