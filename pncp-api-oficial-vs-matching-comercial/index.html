API oficial do PNCP vs serviço de matching comercial: qual a diferença?

A API oficial do PNCP serve para consultar e acompanhar publicações de compras públicas. Um serviço de matching comercial (como o LicitaFit) usa esses dados (ou equivalente) e cruza com o catálogo do cliente para priorizar oportunidades no ERP. São camadas diferentes: portal público versus produto de qualificação comercial.

Resposta direta: PNCP = divulgação e consulta de editais. Matching comercial = cruzar SKUs do cliente com itens do edital e devolver carga de revisão. Comparativo próximo: feed PNCP vs matching.

Quando o product lead precisa de cada um

  • Só PNCP: o software já tem pipeline próprio de ingestão e só precisa de dados brutos
  • Matching comercial: o ERP quer feature “oportunidades alinhadas ao catálogo” sem manter matching, status e alertas de impacto sozinho

Checklist antes de prometer a feature: checklist oportunidades no ERP. Oferta API: para parceiros (R$ 50 / 1.000 requests, mín. R$ 490/mês, R$ 1,90 por licitação monitorada / mês).

O que nenhum dos dois substitui

Nem a API do PNCP nem o matching comercial substituem parecer jurídico, habilitação documental ou a disputa no portal competente. Ver limites do matching e PNCP vs portais de disputa.

Perguntas frequentes

O LicitaFit substitui a API do PNCP?

Não. O LicitaFit é produto de matching comercial sobre oportunidades públicas. O PNCP continua sendo a referência oficial de divulgação.

Posso montar matching só com a API do PNCP?

Tecnicamente um time pode ingerir o feed e construir matching próprio. Isso implica pipeline, modelo de requisitos, UI de revisão e alertas de retificação. O checklist de ERP lista o que entra nesse plano.

Feed bruto e matching são a mesma coisa?

Não. Feed = ingestão de publicações. Matching = cruzar com catálogo e devolver status de requisitos. Ver o comparativo feed vs matching.
