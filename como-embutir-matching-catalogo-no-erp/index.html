Como embutir matching de catálogo no ERP

Para product leads de ERP, comercial/AFV e verticais de TI: planeje a feature “oportunidades alinhadas ao catálogo” com catálogo do cliente, matching, UI de revisão e alertas. A API entrega dados e eventos; o software do parceiro continua dono da interface.

Objetivo: feature paga no software do parceiro que prioriza oportunidades com o catálogo real do cliente (não alerta genérico por palavra-chave). Oferta API: para parceiros.

Cinco blocos da integração

  1. Decidir o escopo da feature

    Use o checklist de oportunidades no ERP (PNCP, catálogo, UI de revisão, alertas de mudança, isolamento por cliente e disclaimer comercial).

  2. Criar catálogo e enviar produtos

    POST /v1/catalogs e PUT /v1/catalogs/{id}/products. Foque no mix que o cliente já vende (hoje: itens do catálogo).

  3. Expor oportunidades na UI

    GET /v1/catalogs/{id}/opportunities alimenta a lista. Mostre SKUs, status de requisitos e needs_review (o que mostrar na feature UI).

  4. Coletar feedback de match

    POST /v1/opportunities/{id}/feedback para a equipe comercial corrigir matches no fluxo do ERP.

  5. Registrar webhooks de alerta

    POST /v1/webhook-endpoints para sinalizar mudança no edital ou no item e pedir reavaliação do matching anterior.

Na UI: carga de revisão, não habilitação

  • Mostre matched, conflito e unknown por requisito
  • Use needs_review como fila comercial
  • Evite rótulos “habilitado”, “aprovado” ou “apto”
  • Inclua disclaimer de apoio à decisão comercial

Vocabulário: status e needs_review. Limites: limites do matching.

Endpoints (visão de produto)

POST /v1/catalogs
PUT  /v1/catalogs/{id}/products
GET  /v1/catalogs/{id}/opportunities
POST /v1/opportunities/{id}/feedback
POST /v1/webhook-endpoints

Detalhe: integração API LicitaFit.

Perguntas frequentes

Por onde começar a embutir matching no ERP?

Comece pelo checklist de product lead. Depois mapeie catalogs, products, opportunities, feedback e webhooks.

A UI do ERP pode rotular o match como habilitado?

Não. Use matched, conflito, unknown e needs_review como carga de revisão comercial (não rotule como habilitado ou aprovado).

Quais endpoints entram no plano de integração?

Os cinco endpoints já publicados na landing (catalogs, products, opportunities, feedback e webhook-endpoints). Sem inventar campos além do exemplo.
