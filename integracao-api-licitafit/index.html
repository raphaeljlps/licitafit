Integração API CruzaEdital (visão de produto)

Na visão publicada na landing, a integração gira em torno de criar catálogo, enviar produtos, listar oportunidades, enviar feedback e registrar webhooks. Esta página espelha esses endpoints e o exemplo de evento (sem inventar campos além do que já está na home).

Fonte: seção “Como funciona” da landing CruzaEdital. Não é documentação OpenAPI completa (é mapa de produto para o PM/engenharia do parceiro).

Endpoints publicados no exemplo

POST /v1/catalogs
PUT  /v1/catalogs/{id}/products
GET  /v1/catalogs/{id}/opportunities
POST /v1/opportunities/{id}/feedback
POST /v1/webhook-endpoints

  1. Catálogo do cliente

    POST /v1/catalogs e PUT /v1/catalogs/{id}/products (o parceiro envia o catálogo que o distribuidor já mantém).

  2. Oportunidades para a UI

    GET /v1/catalogs/{id}/opportunities (oportunidades relevantes, produtos que batem, requisitos a conferir). O que mostrar na tela: feature UI.

  3. Feedback e webhooks

    POST /v1/opportunities/{id}/feedback para correção de matches; POST /v1/webhook-endpoints para receber eventos (ex.: matching e alertas de mudança). Catálogo e feedback isolados por cliente, conforme a home.

Exemplo de evento (campos da landing)

Cada resultado deixa explícito o que bateu, o que conflita, o que ainda é desconhecido (e onde está a evidência no documento). 

{
  "event": "opportunity.matched",
  "product_id": "laptop_16gb_512gb",
  "item_number": 7,
  "qualification": "needs_review",
  "requirements": [
    { "name": "memory", "status": "matched" },
    { "name": "on_site_warranty", "status": "unknown" }
  ],
  "evidence_page": 12
}

Vocabulário de status: matched, conflito, unknown e needs_review. Checklist de escopo: oportunidades de governo no ERP.

O que esta página não inventa

  • Schemas completos, autenticação ou rate limits numéricos
  • Campos além do exemplo publicado na home
  • Garantia de habilitação a partir do evento matched

Documentação de parceiro mais detalhada virá quando estiver estável. Até lá, trate esta página e a landing como a fonte pública de referência.

Perguntas frequentes

Quais endpoints a landing descreve?

POST /v1/catalogs, PUT /v1/catalogs/{id}/products, GET /v1/catalogs/{id}/opportunities, POST /v1/opportunities/{id}/feedback, POST /v1/webhook-endpoints.

Quais campos aparecem no exemplo de evento?

event (opportunity.matched), product_id, item_number, qualification (needs_review), requirements com name e status, e evidence_page.

Esta página é a documentação completa da API?

Não. É visão de produto espelhando o exemplo da landing. Detalhes de autenticação, schemas e limites seguem documentação de parceiro quando estável (sem inventar campos aqui).
